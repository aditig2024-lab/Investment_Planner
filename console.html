Deterministic pipeline · parallel specialists · adviser-gated proposals · monitoring loop

Why Python orders the stages, not an LLM

Suitability before selection and selection before proposal is a regulatory sequence, not a judgement call. A deterministic pipeline enforces it on every run; Agent.as_tool() hand-offs are reserved for places where the route legitimately varies.

Why specialists, not one agent

Goal arithmetic, allocation precedent and rule checking read different data and fail in different ways. Each specialist gets 2–4 tools and returns a typed Pydantic contract, so the Goal Planner can be replayed over 500 profiles and evaluated alone.

Why the context graph

Every booked plan is written back with its reasoning, the peers it was benchmarked against, the rules it satisfied and the adviser who signed it. Rules such as the 40% equity cap on 3–5 year goals carry an ORIGINATED edge to the slipped plan that taught them, so a recommendation can cite its own provenance.

Human-in-the-loop by rule

needs_approval is a callable over the shared PlanContext and the tool arguments. A new plan, any rebalance, a SIP change of ₹10k/month or more, or any rule waiver pauses the run with result.interruptions; RunState is serialisable so the adviser can act hours later.

Monitoring is the same shape

Signals (SIP ledger, NAVs, HR events, fund research) feed a second fan-out; a plain-Python triage() scores severity; the Review Proposer may only propose. Nothing changes in the client's portfolio without the adviser gate.
